# Superpowers routing

Follow the host instruction hierarchy. Skills do not override higher-priority platform instructions; explicit user and project requirements take precedence over workflow preferences.

For non-trivial software-development work, load only the smallest relevant workflow:

- New feature, behavior change, or design decision → `brainstorming`.
- Bug, failed test, or unexpected behavior → `systematic-debugging`.
- A written implementation plan already exists → `executing-plans`.
- A multi-step implementation needs a plan → `writing-plans`.
- Before claiming completion → `verification-before-completion`.
- After a substantial task or before merge → `requesting-code-review`.
- Use domain or implementation skills only when the task actually needs them.

Do not invoke Superpowers for simple factual Q&A, prose-only work, routine file lookup, or tasks with no matching development workflow. Do not create todos or announce skill use unless the selected workflow or task benefits from it.

On Codex, read `references/codex-tools.md` only when tool-name adaptation is actually required.
